# kodo-nav2-patrol

A modular ROS 2 Humble workspace for goal-based robot navigation using TurtleBot3 (Waffle),
Gazebo Classic, and the Nav2 stack — all running inside a reproducible Docker environment.

## Package Structure

```
src/
├── patrol_bringup/       # Launch files & RViz config — single entry point
├── patrol_simulation/    # Gazebo world and spawn configuration
└── patrol_navigation/    # Nav2 params, map files, localization config
```

## Prerequisites

- Docker & Docker Compose (no ROS installation required on the host)
- An X11 server running on the host (for Gazebo + RViz GUI)

## Setup

### 1. Allow X11 forwarding from Docker

```bash
xhost +local:docker
```

### 2. Build the Docker image

```bash
docker compose build
```

This will:
- Pull the `ros:humble-ros-base` base image
- Run `rosdep install --from-paths src --ignore-src -y` to install all declared
  ROS/system dependencies from `package.xml` files
- Run `colcon build --symlink-install`

> **No packages are installed manually** in the Dockerfile. Everything is driven by
> `package.xml` declarations and `rosdep`.

### 3. Add the map file

The pre-built `turtlebot3_world` map PGM is not shipped in this repo.
Copy it from your `turtlebot3_navigation2` installation (or use the one generated by
SLAM Toolbox) into:

```
src/patrol_navigation/maps/turtlebot3_world.pgm
```

The corresponding `turtlebot3_world.yaml` is already provided.

## Usage

### Start an interactive shell inside the container

```bash
docker compose run --rm ros2_nav
```

The `setup_env.sh` script is sourced automatically on login, which:
- Sources `/opt/ros/humble/setup.bash`
- Sources `/ros2_ws/install/setup.bash` (workspace overlay)

### Launch the full system (single command)

```bash
ros2 launch patrol_bringup sim_nav.launch.py
```

This single command:
1. Starts Gazebo Classic with the TurtleBot3 world
2. Spawns the TurtleBot3 Waffle robot
3. Starts Nav2 (map server, AMCL, planner, controller, BT navigator, lifecycle manager)
4. Opens RViz with the patrol configuration

### Sending a navigation goal

**Via RViz (preferred):**
1. Click the **"2D Goal Pose"** button in the RViz toolbar
2. Click and drag on the map to set the goal position and orientation
3. The robot will plan a path and navigate to the goal

**Via CLI:**

```bash
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: 'map'}, pose: {position: {x: 1.0, y: 0.5, z: 0.0}, orientation: {w: 1.0}}}}"
```

## Optional: Build outside Docker

If you have ROS 2 Humble installed natively:

```bash
source /opt/ros/humble/setup.bash
rosdep install --from-paths src --ignore-src -y
colcon build --symlink-install
source install/setup.bash
```

## Assumptions & Limitations

- **Map**: The `turtlebot3_world.pgm` map must be supplied manually (see [Setup](#3-add-the-map-file)).
  It matches the default Gazebo `turtlebot3_world` environment.
- **Localization**: Uses AMCL with the pre-built map. The robot starts at the map origin `(0, 0, 0)`.
  If the initial pose is off, use the **"2D Pose Estimate"** tool in RViz to correct it.
- **Display**: Requires an X11 server on the host. On headless servers, use a virtual display
  (e.g., `Xvfb`).
- **Robot model**: TurtleBot3 Waffle is used (has both LiDAR and camera). Change
  `TURTLEBOT3_MODEL` in `setup_env.sh` or `docker-compose.yml` to use `burger`.
